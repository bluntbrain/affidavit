**Update since submission: the bridge's Ethereum half, the seam and recovery now run**

Since posting this proposal I have built and tested the parts of Causeway that can exist before the LEZ bridge program does. Everything is in [`bridge/`](https://github.com/bluntbrain/affidavit/tree/main/bridge) of the Affidavit repository, under CI.

1. **The Ethereum vault** — [`CausewayVault.sol`](https://github.com/bluntbrain/affidavit/blob/main/bridge/contracts/src/CausewayVault.sol). Deposits of native ETH, ERC-20s and USDT-style no-return tokens on a fixed denomination grid (F1, F8, F17); immutable pairing to one chain, vault, LEZ zone, program and burn image (F15, Security 8); independent admin (RFP-001) and freezer (RFP-002) roles (F14, Security 5); per-token value caps and global operation caps over a rolling window (F11); `release(seal, journal)` on a proven LEZ burn, in this order: pairing → LEZ finality anchor → replay → RISC Zero Groth16 verification of the journal → freeze → caps → supply → pay (F5–F7, F12, Security 2, #3, #6). 21 tests on an in-process EVM, including: a relayer cannot redirect, inflate or re-target a release; a proof for another chain, vault, zone or program is refused; delisting a token stops deposits but keeps escrow releasable; raising the finality depth never invalidates an already-final root. Measured gas: deposit 86k (ETH) / 109k (ERC-20); release 160k (ERC-20) / 98k (ETH) before the verifier's own cost.

2. **The seam, on real receipts** — [`tests/seam.rs`](https://github.com/bluntbrain/affidavit/blob/main/bridge/tests/seam.rs). Affidavit's real receipt-proof path attests a `Deposit` log that the compiled vault emitted on a real EVM; the depositor's seed-derived secret opens the deposit's commitment and yields a one-time nullifier `H(s, id)` that is unique per deposit and not computable by an observer (Privacy 1, Reliability 3, Security 3). Someone else's deposit, a replay, a wrong vault, denomination, instance or network, and a genuine mainnet ERC-20 `Transfer` are all refused.

3. **Recovery from the seed alone** (F9, Reliability 5) — the derivation and the gap-limited scan in Rust and in JavaScript, pinned to one shared vector, run against real `Deposit` logs: a restored client finds exactly its own deposits and nothing else ([`docs/RECOVERY.md`](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/RECOVERY.md)).

4. **Design documents** — [architecture](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/DESIGN.md) with the trust table, invariants and the failsafe; the [outbound leg](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/OUTBOUND.md) with the two routes for the LEZ settled-state anchor and what M0 measures; [privacy](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/PRIVACY.md) as testable properties, with the residual correlations listed rather than waved away; [costs](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/COSTS.md) separating measured from estimated; and the [combined RFP-021 + RFP-022 plan](https://github.com/bluntbrain/affidavit/blob/main/bridge/docs/COMBINED.md): dependencies, a 27-week timeline for one engineer, and the $92,000 combined price.

What this does not yet show: the LEZ bridge program, the burn guest and its Groth16 wrapping, and the settled-state anchor. Those are the grant (M0–M2). The release gas above uses a mock verifier; the real Groth16 verification cost is an M0 measurement.

The companion RFP-021 proposal (#247) has its own update: Affidavit's privately-proven `Verify` advancing public state through LEZ v0.4.0-rc1's execution state machine.
